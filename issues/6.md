### Summary

`serialize_to_turtle()` interpolates `confidence` as a bare token with no type check:

```python
confidence = entity.get("confidence", 1.0)
...
lines.append(f"    semantica:confidence {confidence} .")
```

Nothing in the dict-based API validates the type of `confidence`, so a string, `None` or a bool reaches the serializer unchanged and produces invalid Turtle.

### Version

semantica 0.6.5, Python 3.13.

### Reproduction

```python
from semantica.export.methods import export_rdf
kg = {"entities": [{"id": "https://example.org/e2", "name": "X",
                    "type": "https://example.org/Person",
                    "confidence": "high"}],
      "relationships": []}
export_rdf(kg, "out.ttl", format="turtle")
```

### Actual

```turtle
<https://example.org/e2> a <https://example.org/Person> ;
    semantica:text "" ;
    semantica:confidence high .
```

- Oxigraph: `Parser error at line 7 between columns 26 and 30: high is not a valid RDF object`
- rdflib 7.x: `BadSyntax (objectList expected)`

`None` produces `semantica:confidence None .` and `True` produces `semantica:confidence True .`, both invalid for the same reason. Python's `True` is also not the Turtle boolean literal `true`.

### Expected

Coerce to a typed literal and validate: `"0.91"^^xsd:decimal` for numbers, an explicit error or an omitted triple for non-numeric values. The N-Triples serializer already emits `"0.91"^^xsd:float` for the same field, so the two paths should be reconciled at the same time (see the companion report on cross-format divergence).

### Note

`RDFExporter.export_to_rdf()` does call `RDFValidator.validate_rdf_syntax()` before serializing, and it logs `Continuing with export, but data may be invalid` rather than failing. In this case it does not flag the value at all, so the warning never fires and an unparseable file is written silently.
