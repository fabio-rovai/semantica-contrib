### Summary

Every RDF export mints terms in `https://semantica.dev/ns#`: `semantica:text`, `semantica:confidence`, `semantica:openEndedInterval`, the synthesised entity IRIs, and the default type `semantica:Entity`. The provenance exporter mints under the same base by design (`DEFAULT_BASE_URI`, so KG and PROV URIs co-resolve).

That namespace has no vocabulary behind it.

### Evidence

```
$ curl -sSL -H 'Accept: text/turtle, application/rdf+xml' -o /dev/null -w '%{http_code} %{content_type}\n' https://semantica.dev/ns
404 text/html;charset=utf-8
```

and the distributed package contains no RDF vocabulary of any kind:

```
$ find $(python -c 'import semantica,os;print(os.path.dirname(semantica.__file__))') \
    -name '*.ttl' -o -name '*.owl' -o -name '*.rdf' -o -name '*.jsonld'
(no results)
```

semantica 0.6.5, installed from PyPI.

### Why this matters beyond tidiness

1. **Nothing declares what the terms mean.** A consumer receiving a Semantica export cannot determine whether `semantica:confidence` is an annotation property, a datatype property, what its range is, or whether `semantica:text` is intended as an `rdfs:label` equivalent. There is no document to consult and no document to fetch.
2. **No consumer can tell a real term from a typo.** In the open world an undeclared IRI is unknown, not wrong, so `semantica:txet` and `semantica:text` are equally valid to every RDF tool. Closed-world checking is the only thing that separates them, and it requires a published vocabulary to check against. With none, that check cannot be run at all: pointed at a Semantica export, the closed-world checker in [open-ontologies](https://github.com/fabio-rovai/open-ontologies) reports `no ontology vocabulary found (0 declared terms), nothing was checked` rather than a verdict.
3. **It undercuts the interoperability claim.** The project describes itself as W3C standards compliant with full provenance. Emitting PROV-O alongside terms from an unresolvable namespace means the PROV half is checkable and the payload half is not.

### What resolving this would look like

Publishing a small vocabulary at `https://semantica.dev/ns#` declaring the handful of terms the exporters actually emit, with `rdfs:domain`, `rdfs:range` and labels, and content negotiation so the IRIs dereference. The set is small: I count six terms across the RDF, OWL-Time and provenance paths.

Related: #1101 covers a second problem with the same namespace, where the fallback path writes `<semantica:entity_N>`, an IRI in the scheme `semantica` rather than the prefix expansion, so those terms would not resolve even once the namespace does.
