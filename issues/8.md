### Summary

`SHACLGenerator` defaults `base_uri` to `https://semantica.dev/shapes/` and mints **both** the shape IRIs and the `sh:targetClass` / `sh:path` IRIs under it. Every other module mints terms under `https://semantica.dev/ns#` (`RDFSerializer`'s `semantica` prefix, `OWLExporter`'s `ont` prefix, `ProvenanceManager.DEFAULT_BASE_URI`).

The generated shapes therefore target classes that no other part of the package ever produces, so validation matches zero focus nodes and reports conformance regardless of the data.

### Version

semantica 0.6.5, Python 3.13.

### Reproduction

```python
from semantica.ontology.ontology_generator import SHACLGenerator

onto = {
    "classes": [{"name": "Person", "label": "Person"}],
    "properties": [{"name": "fullName", "type": "datatype", "domain": "Person",
                    "range": "string", "required": True}],
}
gen = SHACLGenerator()
open("shapes.ttl", "w").write(gen.serialize(gen.generate(onto), "turtle"))
```

produces

```turtle
@prefix ex: <https://semantica.dev/shapes/> .
<https://semantica.dev/shapes/PersonShape>
    a sh:NodeShape ;
    sh:targetClass ex:Person ;
    sh:property [ sh:path ex:fullName ; sh:datatype xsd:string ; sh:minCount 1 ; ... ] .
```

Now validate an instance of the class as any other Semantica module would write it:

```turtle
@prefix ont: <https://semantica.dev/ns#> .
<https://example.org/p1> a ont:Person .          # missing the required fullName
```

```python
from pyshacl import validate
import rdflib
d = rdflib.Graph().parse("data.ttl", format="turtle")
s = rdflib.Graph().parse("shapes.ttl", format="turtle")
print(validate(d, shacl_graph=s)[0])
```

### Actual

`True` (conforms). The instance is missing a property the shape declares `sh:minCount 1`, and validation passes, because `ex:Person` (`https://semantica.dev/shapes/Person`) and `ont:Person` (`https://semantica.dev/ns#Person`) are different IRIs.

Changing only the data namespace to `https://semantica.dev/shapes/` makes the same instance report `False` with the expected `MinCountConstraintComponent` violation, confirming the shapes themselves are fine and it is purely the namespace that does not line up.

### Why this is worse than a normal false negative

A SHACL run that matches nothing is indistinguishable, in its report, from a SHACL run where everything passed. `conforms: True` with zero focus nodes is the output either way, so a pipeline that validates before publishing gets a green light on unvalidated data.

### Expected

One namespace default across the package, or `SHACLGenerator` taking the target namespace from the ontology dict rather than from its own `base_uri`. Separately, it would be worth reporting the focus-node count in the validation report so an empty match is visible.
