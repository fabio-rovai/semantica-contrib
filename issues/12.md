### Summary

`method_registry` is documented as the surface for "community-contributed extensions", but a registered method cannot fail. `export_rdf` (and its siblings) wrap the custom call in a bare `except Exception` and fall back to the default implementation:

```python
custom_method = method_registry.get("rdf", method)
if custom_method and custom_method is not export_rdf:
    try:
        return custom_method(data, file_path, format=format, **kwargs)
    except Exception as e:
        logger.warning(f"Custom method {method} failed: {e}, falling back to default")
```

So any extension whose purpose is to *refuse* something (validation, policy, schema gating, a pre-publication check) is silently downgraded to the behaviour it was registered to prevent. The failure is logged at warning level and the caller receives a normal return.

### Version

semantica 0.6.5, Python 3.13.

### Reproduction

Register a method that verifies the exported RDF and raises when it is unsound:

```python
from semantica.export.registry import method_registry
from semantica.export.rdf_exporter import RDFExporter
from semantica.export.methods import export_rdf
from semantica.kg.graph_builder import GraphBuilder
from pathlib import Path

class VerificationError(RuntimeError): pass

def verified(data, file_path, format="turtle", **kw):
    path = Path(file_path)
    RDFExporter().export(data, path, format=format, **kw)
    # any independent RDF 1.1 parser will do here
    from open_ontologies_lite import OntologyEngine
    result = OntologyEngine.validate(path.read_text(), format)
    if not result.ok:
        path.unlink(missing_ok=True)
        raise VerificationError(result.error)
    return result

method_registry.register("rdf", "verified", verified)

kg = GraphBuilder(resolve_conflicts=False).build(sources=[{
    "entities": [{"id": "Acme Corp", "name": "Acme Corp", "type": "ORG", "confidence": 0.9}],
    "relationships": [],
}])
export_rdf(kg, "out.ttl", format="turtle", method="verified")
```

### Actual

```
WARNING  Custom method verified failed: Parser error at line 5 between columns 1 and 12:
         Invalid IRI code point ' ', falling back to default
```

`out.ttl` exists, 358 bytes, containing `<Acme Corp> a <ORG> ;`, which no RDF 1.1 parser accepts. The gate ran, correctly identified the problem, deleted the file, and the fallback wrote it back. `export_rdf` returned normally, so nothing downstream can tell that verification failed.

### Why the fallback is the wrong default here

Falling back makes sense for a method that is merely *unavailable*, say an optional dependency that is not installed. It is the opposite of what is wanted for a method that is *asserting something is wrong*. As written the two cases are indistinguishable, and the more dangerous one wins: the export that a check just rejected is the one that ends up on disk.

The same pattern appears in `export_json`, `export_csv`, `export_owl` and the other `export_*` wrappers, so the behaviour is consistent across the registry rather than specific to RDF.

### Effect on what can be built

This forecloses a category of extension rather than making one awkward: anything that gates, validates, enforces a policy, or refuses to emit. Those are the extensions most worth contributing to an accountability platform, and today the registry cannot express them.

I hit this building a verification adapter against 0.6.5, which is how the reproduction above was found rather than constructed.
