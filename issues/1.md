### Summary

`RDFSerializer.convert_kg_to_rdf()` (`semantica/export/rdf_exporter.py:249`) is the method that normalises an entity's `name` into `label`/`text`. It is defined but never called anywhere in the package, so no public export path ever runs it. `serialize_to_turtle()` then reads `entity.get("text") or entity.get("label", "")`, finds neither key on graphs produced by `GraphBuilder` (which emits `name`), and writes an empty string.

Result: every entity in every RDF export has an empty label. The human-readable content of the graph is silently dropped.

### Version

semantica 0.6.5 (pip, `semantica[shacl,tripletstore-oxigraph]`), Python 3.13.

### Reproduction

```python
from semantica.kg.graph_builder import GraphBuilder
from semantica.export.methods import export_rdf

source = {
    "entities": [
        {"id": "https://example.org/acme", "name": "Acme Corp",
         "type": "https://example.org/Org", "confidence": 0.91},
    ],
    "relationships": [],
}
kg = GraphBuilder(resolve_conflicts=False).build(sources=[source])
export_rdf(kg, "out.ttl", format="turtle")
print(open("out.ttl").read())
```

### Actual

```turtle
<https://example.org/acme> a <https://example.org/Org> ;
    semantica:text "" ;
    semantica:confidence 0.91 .
```

### Expected

```turtle
<https://example.org/acme> a <https://example.org/Org> ;
    semantica:text "Acme Corp" ;
    semantica:confidence 0.91 .
```

### Why it is easy to miss

The output is valid Turtle and parses cleanly in both rdflib and a strict RDF 1.1 parser (Oxigraph). Nothing errors, nothing warns. The triple count is correct. Only the values are gone, so a round-trip test that counts triples or checks conformance will pass.

### Suggested fix

Call `convert_kg_to_rdf()` from `RDFExporter.export_to_rdf()` before dispatching to a serializer, so every format benefits, rather than fixing the key lookup in each `serialize_to_*` method separately. A regression test asserting a non-empty `semantica:text` for a `GraphBuilder` graph would have caught this.

Verified against the same input with two independent parsers. Happy to open a PR if the maintainers prefer the fix at the `export_to_rdf` boundary.
