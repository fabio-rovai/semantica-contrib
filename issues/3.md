### Summary

`serialize_to_turtle()` writes entity ids and types straight into `<...>` with no IRI validation:

```python
lines.append(f"<{entity_id}> a <{entity_type}> ;")
```

`GraphBuilder._process_item()` (`semantica/kg/graph_builder.py:141-146`) defaults `id` to the entity's surface text and `type` to the extractor's label. So the default pipeline path, with no unusual input, emits IRIs containing spaces.

### Version

semantica 0.6.5, Python 3.13.

### Reproduction

```python
from semantica.kg.graph_builder import GraphBuilder
from semantica.export.methods import export_rdf

source = {
    "entities": [
        {"id": "Acme Corp", "name": "Acme Corp", "type": "ORG", "confidence": 0.91},
        {"id": "Jane Doe", "name": "Jane Doe", "type": "PERSON", "confidence": 0.88},
    ],
    "relationships": [
        {"source": "Jane Doe", "target": "Acme Corp", "type": "works_for", "confidence": 0.8},
    ],
}
kg = GraphBuilder(resolve_conflicts=False).build(sources=[source])
export_rdf(kg, "out.ttl", format="turtle")
```

### Actual

```turtle
<Acme Corp> a <ORG> ;
    semantica:text "" ;
    semantica:confidence 0.91 .

<Jane Doe> <works_for> <Acme Corp> .
```

- Oxigraph (strict RDF 1.1): `Parser error at line 5 between columns 1 and 12: Invalid IRI code point ' '`
- rdflib 7.x: parses, but resolves the relative reference against the file location and warns `file:///.../out/Acme Corp does not look like a valid URI, trying to serialize this will break`

The second behaviour is the more dangerous one: the export looks like it worked, and the graph silently acquires `file://` identity that will not match anything downstream.

### Expected

Either reject non-IRI ids with a clear error, or mint a stable IRI in the `semantica:` namespace by percent-encoding or slugging the label. Bare relative references such as `<ORG>` and `<works_for>` should not be emitted at all, since there is no `@base` in the output.

### Note

`semantica/triplet_store/` already validates IRIs before SPARQL interpolation (#911). The export path has no equivalent check, so the two surfaces disagree about what a valid identifier is.

### Suggested fix

An `_as_iri(value, fallback_ns)` helper used by every serializer, plus a validation pass in `RDFValidator.validate_rdf_syntax()` that actually fails on invalid IRIs. Today that validator runs before serialization and does not catch this.
