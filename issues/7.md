### Summary

`OntologyGenerator` emits ontology dicts shaped `{"classes": [...], "properties": [...]}` (see `ontology/ontology_generator.py:409, 458-459, 482-483`), and `SHACLGenerator` consumes exactly that shape. `OWLExporter` reads a different schema:

- class IRI from `cls.get("uri") or cls.get("id", "")` (`export/owl_exporter.py:392`), never `name`
- properties from `ontology.get("object_properties", [])` and the datatype equivalent, never `properties`

So feeding the OWL exporter the output of the project's own ontology generator produces a file in which every class has an empty IRI and no property is exported at all.

### Version

semantica 0.6.5, Python 3.13.

### Reproduction

```python
from semantica.export.methods import export_owl

ontology = {
    "classes": [{"name": "Person", "label": "Person"},
                {"name": "Organization", "label": "Organization"}],
    "properties": [
        {"name": "fullName", "type": "datatype", "domain": "Person", "range": "string", "required": True},
        {"name": "foundedOn", "type": "datatype", "domain": "Organization", "range": "date"},
    ],
}
export_owl(ontology, "onto.ttl", format="turtle")
print(open("onto.ttl").read())
```

### Actual

```turtle
<https://semantica.dev/ns#> a owl:Ontology ;
    rdfs:label "SemanticaOntology" ;
    owl:versionInfo "1.0" .

<> a owl:Class ;
    rdfs:label "Person" .

<> a owl:Class ;
    rdfs:label "Organization" .
```

Three consequences:

1. `<>` is the empty relative IRI, which denotes the document itself. Both classes are therefore the **same node**, and that node is also the ontology document.
2. A strict RDF 1.1 parser rejects the file outright: Oxigraph gives `Parser error at line 11 between columns 1 and 3: No scheme found in an absolute IRI`.
3. All three properties are missing. The output is silent about this; no warning is logged.

### Expected

`export_owl` should accept the shape `OntologyGenerator` produces: mint class IRIs from `name` under the ontology namespace when `uri`/`id` is absent, and read `properties` (splitting on `type`) in addition to `object_properties`/`datatype_properties`. Failing that, it should raise rather than emit `<>`.

### Note

#478 fixed an earlier invalid-Turtle-and-dropped-properties bug in this same exporter. The underlying schema mismatch between the generator and the exporter was not addressed, so the same symptom returns through the generator path.
